# App behaviour reference (for the lawyer)

> **DRAFT – not legal advice – lawyer review required.** Read from the source code on 4 Oct 2026 (updated for refund approval, consent log, export/delete, retention, avatars). Use it to check that each document says what the product really does. "Setting" = an admin-editable platform setting (defaults from the database migrations).

| Topic | What the app does | Source |
|---|---|---|
| Customer cancel cut-off | Allowed while the appointment is **≥ `cancel_cutoff_min` away** (default **30**, admin setting 0–1440); after that the API refuses. The app shows the live value. | `platform_settings.cancel_cutoff_min`, `customerCancel` in `src/bookingService.ts` |
| Cancel in time, **paid online** | Payment status becomes **REFUND_PENDING** and the Paystack payment `refund_status` **PENDING_APPROVAL** with a due time = cancel time + `refund_auto_approve_hours` (default **3**). **No credit is ever created.** Admin can approve (PIN required) or reject (written reason, customer notified: no refund and no credit). If nobody decides by the due time, the sweeper **auto-approves** (system actor, no PIN) and requests the refund from Paystack; failures raise an admin alert and are retried. Exactly-once: a second decision is refused. The old switch `credit_on_early_cancel_prepaid` is **ignored**. | `src/refundFlow.ts`, `src/bookingService.ts`, `src/sweep.ts`, `src/paystack.ts` |
| Cancel in time, paid by **plan session / credit** | Session or credit is restored automatically. | `restoreEntitlement` |
| Cancel in time, **pay on arrival** or **unpaid attempt** | Booking cancelled, payment VOID. An unpaid "Pay now" attempt that the customer cancels is "Incomplete" and the barber is not told. | `customerCancel` |
| **No-show** | Barber can mark only **after** the scheduled time. Paid online or plan-paid session → **no refund**, **1 credit** (value = booking price) with the **same barber**, issued **immediately** (no admin approval), if setting `credit_on_missed_session` (default **on**). A booking that already has a refund never also gets a credit (`issueCredit` refuses). A booking paid with a credit is not re-credited. Unpaid/pay-on-arrival → payment VOID. Customer notified. | `barberAction('no-show')`, `issueCredit` |
| **Credit** | Same barber only; expires after `credit_expiry_days` (default **30**); must be used for an appointment starting before expiry; service price must be ≤ credit value; one credit per source booking; "not cashable" (no cash-out feature exists). | `issueCredit`, `claimEntitlement` in `src/plans.ts` |
| **Not served** (barber) | Plan session/credit restored; paid online → **REFUND_PENDING** (the same refund approval flow, no credit); others VOID. | `barberAction('not-served')` |
| **Unpaid hold** | Pay-now attempt holds the slot `payment_hold_min` (default **15**, admin setting); expired attempts are closed lazily and by the sweeper → "Incomplete", no charge, barber never sees them. A payment that arrives late is confirmed if the slot is still free. | `platform_settings.payment_hold_min`, `expireHolds`, `applyVerifiedPayment` |
| **Duplicate / late / slot-taken payment** | Booking not confirmed; payment flagged **NEEDS_REFUND**; refund requested from Paystack automatically; failed refund calls retried by the sweeper. Customer notified. | `applyVerifiedPayment`, `processReference`, `requestRefund`, `src/sweep.ts` |
| Amount check | Gateway amount must equal price plus a plausible processing fee (≤ 8 % or ₦200); otherwise not confirmed, left for staff. Paystack "pass-the-fee" mode is in use in test (customer paid price + fee). | `amountMatches` in `src/paystack.ts` |
| Admin removes customer/barber | Upcoming bookings cancelled; paid online ones flagged NEEDS_REFUND and refunded; plan sessions/credits restored. Soft delete restorable **30 days**; **hard delete refused when a successful payment exists**. | `src/adminDelete.ts` |
| **Plan limits** | Price (settings `min/max_plan_price`, defaults ₦1,000–₦500,000), validity ≤ `max_plan_validity_days` (**90**), sessions ≤ `max_plan_sessions` (**30**). Purchase snapshot of terms; edits affect only future buyers. Active only after verified payment; validity counted from payment. Unused sessions: `plan_refund_policy` **NONE** (default) or MANUAL (display only). Never-paid plan checkouts deleted after `retention_checkout_days` (**2**) after a gateway check. | `src/plans.ts`, `src/sweep.ts`, migrations 004, 011 |
| Plan session use | Needs a valid plan with the service included and the appointment on or before expiry; one session per booking. | `claimEntitlement` |
| **Platform fee** | `platform_fee_naira` + `platform_fee_percent` of price, capped at price; if both are 0 the server environment values apply; per-barber override possible (even 0). Production at time of writing: **₦10 + 0.15 %**. Taken via Paystack split (`transaction_charge`). The public settings endpoint reports the effective fee. | `src/ledger.ts` (`inAppFeeKobo`), `src/paystack.ts`, `src/publicSettings.ts` |
| **Cash commission** | On a COMPLETED, PAID **pay-on-arrival** booking: debt = `commission_factor` (default **0.5**, shown publicly as **50 %**) × the in-app fee for that price; one ledger row per booking; setting `commission_enabled`. | `accrueCommission`, `src/ledger.ts` |
| **Netting** | On the barber's next online payments, the platform charge is raised by up to the outstanding debt, never beyond it, and so the barber keeps at least `min_barber_payout_percent` (default **50 %**) of the amount; FIFO; applied to the ledger only when the payment is confirmed; reversed on refund. | `nettableKobo`, `planCheckoutSplit`, `applyNettingForPayment`, `reverseNettingForPayment` |
| Balance limits | `ledger_max_debt` and `ledger_max_age_days` (default **0 = no limit**). If exceeded, the shop stops offering pay-on-arrival. Reminders at most every 3 days. Admin can waive/adjust/settle manually. | `ledgerBlocked`, `sendLedgerReminders` |
| **Payout set-up** | Barber picks bank (Paystack list, cached 6 h), enters 10-digit account; name looked up with Paystack (retry once); if lookup unavailable barber types the name (flag `payout_name_verified = false`); subaccount created at Paystack; we store bank name, **last 4 digits**, account name, subaccount code. Without payout set-up customers can only pay on arrival (production requires payout). Paystack **test mode** allows only 3 real-account lookups per day. | `src/payouts.ts`, migration 010 |
| **Shop approval** | Statuses PENDING, NEEDS_INFO, REJECTED, VERIFIED, SUSPENDED; only VERIFIED shops are visible/bookable; suspension reversible. | `src/admin*.ts` |
| Maintenance mode | Admin switch pauses new bookings and plan purchases with a message; existing bookings continue. | `platform_settings.maintenance_mode` |
| **Accounts** | Name, e-mail and/or phone (at least one), password (bcrypt). JWT in HttpOnly cookie `trimslot_token`, **7 days**, SameSite=Lax, Secure in production. Suspended/banned accounts are treated as logged out. Failed-login lock after 8 in 15 min per account; rate limits per IP. | `src/auth.ts`, `src/security.ts` |
| Age | No age check in the app; no date of birth collected. | — |
| Reviews / reports | Reviews for completed visits (barber can reply, admin can hide). Reports with categories NO_SHOW, BEHAVIOUR, PAYMENT, QUALITY, SAFETY, OTHER (message 5–1000 chars) go to admin. | `src/app.ts`, `src/admin2.ts` |
| Reliability label | "New / Reliable / Mostly reliable / Often misses" with counts, shown to barbers about customers. | `reliabilityOf` in `src/smart.ts` |
| Private barber notes | Barber can store a note about a customer; visible only to that barber. | `barber_customer_notes` |
| Push | Web Push (VAPID); subscription = endpoint + keys stored with the user; removed when the push service reports it gone or on unsubscribe. Reminders about 2 h and 30 min before; "your turn"/queue messages. In-app notifications always stored. | `src/push.ts`, `src/smart.ts`, `public/notify.js` |
| Data storage | Supabase Postgres, **eu-west-2 (London)**; Vercel functions region **lhr1 (London)**. Shop photo stored in the database (≤ 300 KB). | Supabase project, `vercel.json` |
| Retention automation | An hourly-throttled job (in the cron sweep; also "Run clean-up now" in admin Controls, PIN) deletes: rate-limit rows (`retention_rate_limit_hours`, 2 h); payment webhook events (`retention_events_days` 400; invalid-signature ones `retention_bad_events_days` 30); notifications (`retention_notifications_days` 180); stale push subscriptions (`retention_push_stale_days` 60); admin alerts (`retention_admin_alerts_days` 90); soft-deleted users past `retention_deleted_days` (30): erased when no successful payment exists, otherwise anonymised; soft-deleted reviews, reports, and plans without purchases after the same window; abandoned plan checkouts (`retention_checkout_days` 2). Bookings, payments, refunds and the audit trail are kept (anonymised after account deletion). All periods are admin settings. | `src/retention.ts`, `src/sweep.ts`, migration 011 |
| Self-service rights | **Download my data** (`GET /api/me/export`, JSON; no password hash; barber private notes excluded). **Delete my account** (`POST /api/me/delete`, password + typing DELETE): customers are deleted at once unless they have upcoming bookings (blocked) and must acknowledge losing unused plan sessions/credits; barbers are deleted at once only with no upcoming bookings, no commission owed and no active customer plans, otherwise a deletion **request** is recorded and an admin alert raised (can be cancelled). Deletion = anonymisation: name, contact, picture, notifications, favourites, waitlist, notes and push subscriptions removed; payments, bookings and the audit trail kept without the name. | `src/accountData.ts` |
| Logs | Request log lines contain method, path, status, IP and user ID (stdout → Vercel). | `src/logger.ts`, `src/app.ts` |
| **Editable published numbers** | Cancel lock, pay-now hold, credit expiry, refund auto-approve hours, fee %, flat fee, commission factor, liability cap, plan limits, retention periods and document versions are all admin settings (Controls page and Platform rules), validated server-side and audited (`SETTINGS_UPDATED` with before/after). The public pages (Terms, Privacy, Refunds, Plan Terms, Cookies, Barber Agreement) fill these numbers in live from `GET /api/public-settings` (no secrets, cached 60 s). The liability cap is **0 = not set** and the Terms then shows a placeholder. | `src/plans.ts`, `src/publicSettings.ts`, `public/legal-live.js` |
| **Admin alerts** | In-app list + web push to the admin for: refund waiting, refund auto-approved, refund failed (12 h dedupe), barber deletion request. Per-event in-app/push preferences and optional quiet hours (default 22:00–07:00 Lagos, off) hold pushes until quiet hours end. Admin push subscriptions are separate from customer ones. | `src/adminNotify.ts`, `public/admin5.js`, `public/sw.js` |
| **Customer profile picture** | Customers only, optional. Cropped to a square and compressed to a ≤ 100 KB JPEG in the browser (server limit 120 KB, type checked by content), stored in the database (`user_avatars`) like the shop photo. Visible to the customer, to a barber who has a booking or waitlist entry with them, and to admin. Admin can remove a photo with a reason (customer notified, audited). Deleted with the account. | `src/avatars.ts`, `public/account.js` |
| Refund decision rights | Approve needs the admin PIN. Reject needs a reason. Auto-approve needs neither. Legacy CREDIT_PENDING rows from before this rule stay resolvable (credit or refund) in "Refund decisions"; no data was migrated. | `src/refundFlow.ts`, `src/admin.ts` |
| Terms acceptance | Sign-up requires a tick-box: customers accept Terms + Privacy; barbers also the Barber Agreement. Each acceptance is stored in `consent_log` (document, version, time, source, IP, user agent; IP and user agent are nulled when the account is deleted). Versions are admin settings (`terms_version`, `privacy_version`, `barber_agreement_version`); when one is raised every user without the new version sees a blocking re-accept page. Admin sees the history in the user record. Accounts created before this existed have no record and are asked at next login. | `src/accountData.ts`, `public/account.js`, migration 011 |
