# App behaviour reference (for the lawyer)

> **INTERNAL – for the owner and the lawyer only. Do NOT publish this file or the legal pack** (no web page, no public repository, no app screen). It contains business details such as fees, charges, the split of processing costs and internal settings. Only files 01–06 are turned into public pages, and they must not quote those numbers.

> **DRAFT – not legal advice – lawyer review required.** Read from the source code on 4 Oct 2026 (updated for refund approval, consent log, export/delete, retention, avatars). Use it to check that each document says what the product really does. "Setting" = an admin-editable platform setting (defaults from the database migrations).

| Topic | What the app does | Source |
|---|---|---|
| Customer cancel cut-off | Allowed while the appointment is **≥ `cancel_cutoff_min` away** (default **30**, admin setting 0–1440); after that the API refuses. The app shows the live value. | `platform_settings.cancel_cutoff_min`, `customerCancel` in `src/bookingService.ts` |
| Cancel in time, **paid online** | Payment status becomes **REFUND_PENDING** and the Paystack payment `refund_status` **PENDING_APPROVAL** with a due time = cancel time + `refund_auto_approve_hours` (default **3**). **No credit is ever created.** Admin can approve (PIN required) or reject (written reason, customer notified: no refund and no credit). If nobody decides by the due time, the sweeper **auto-approves** (system actor, no PIN) and requests the refund from Paystack; failures raise an admin alert and are retried. Exactly-once: a second decision is refused. The old switch `credit_on_early_cancel_prepaid` is **ignored**. | `src/refundFlow.ts`, `src/bookingService.ts`, `src/sweep.ts`, `src/paystack.ts` |
| Cancel in time, paid by **plan session / credit** | Session or credit is restored automatically. | `restoreEntitlement` |
| Cancel in time, **pay on arrival** or **unpaid attempt** | Booking cancelled, payment VOID. An unpaid "Pay now" attempt that the customer cancels is "Incomplete" and the barber is not told. | `customerCancel` |
| **No-show** | Barber can mark only **after** the scheduled time. Paid online or plan-paid session → **no refund**, **1 credit** (value = the booking's `price_kobo`, i.e. the service price at booking; for a plan session this is the service price, not the per-session share of the plan price, so it can be higher than what the session cost — owner to confirm) with the **same barber**, issued **immediately** (no admin approval), if setting `credit_on_missed_session` (default **on**). A booking that already has a refund never also gets a credit (`issueCredit` refuses). A booking paid with a credit is not re-credited. Unpaid/pay-on-arrival → payment VOID. Customer notified. | `barberAction('no-show')`, `issueCredit` |
| **Credit** | Same barber only; expires after `credit_expiry_days` (default **30**); must be used for an appointment starting before expiry; service price must be ≤ credit value; one credit per source booking; "not cashable" (no cash-out feature exists). | `issueCredit`, `claimEntitlement` in `src/plans.ts` |
| **Loyalty credit** | Off by default (`feature_loyalty`). When on, every `loyalty_every_n`th (default 10) COMPLETED booking with the same barber earns one credit worth `loyalty_credit_kobo` (default ₦1,000), valid a fixed **90 days** (not `credit_expiry_days`); one per source booking; customer notified. | `afterComplete` in `src/smart.ts` |
| **Credit revoked by admin** | Admin can revoke an AVAILABLE credit (single or in bulk) with a reason; the customer is notified; audited (`ADMIN_CREDIT_REVOKED`). PIN needed. | `src/admin2.ts`, `src/admin3.ts` |
| **Not served** (barber) | Plan session/credit restored; paid online → **REFUND_PENDING** (the same refund approval flow, no credit); others VOID. | `barberAction('not-served')` |
| **Unpaid try (no slot reserved)** | A pay-now attempt reserves **no slot**: the slot stays visible and bookable to everyone while it is open (`busyIntervals` ignores PENDING_PAYMENT), and the first confirmed payment wins (the slot is re-checked under the barber lock at confirmation). The attempt stays open `payment_hold_min` (default **15**, admin setting); Starting to pay extends the try to now + `payment_hold_min`, never beyond 4 × `payment_hold_min` from when the try was made; pressing Pay again re-uses the same open Paystack checkout (same reference) instead of making another. Before a try is closed (lazy close or sweeper), `verifyBeforeClosing` asks Paystack about its INITIATED payments (throttled 2 min per reference through `rate_limits`): paid → confirmed or refunded as below; not paid → "Incomplete" with "You were not charged"; Paystack unreachable → kept open up to 60 min after the hold ended, then closed with a hedged message (no "not charged"). The sweeper (`reconcileRecentPayments`, 10-min throttle) also re-checks INITIATED booking payments created in the last 48 h whose booking is Incomplete or still pending. → "Incomplete", barber never sees it. **Late payment:** if the closed attempt was closed by time only (not cancelled by the customer or by a shop removal), is still in the future, the shop is verified and not paused, and the time is still free, the payment **confirms the booking** (`PAYMENT_CONFIRMED`), whether or not the sweep has run; otherwise it is flagged NEEDS_REFUND. | `platform_settings.payment_hold_min`, `expireHolds`, `applyVerifiedPayment` |
| **Duplicate / late / slot-taken payment** | Booking not confirmed; payment flagged **NEEDS_REFUND**; refund requested from Paystack automatically; failed refund calls retried by the sweeper. The customer gets a notification in all three cases (duplicate: "We got a second payment. Your refund is coming."). Each has its own result (`duplicate_refund`, `late_refund`, `slot_taken`), kept when asked again, and its own text on the booking page (derived from the booking and payment on every load, so it survives the 10-second refresh; a cancelled booking never says "confirmed"). **Amount or currency mismatch** (`amount_mismatch`: amount ≠ price + booking fee within tolerance, or currency present and not NGN): not confirmed, not auto-refunded; audit `PAYMENT_AMOUNT_MISMATCH`, customer notification `PAYMENT_PROBLEM`, admin alert `PAYMENT_MISMATCH` (24 h dedupe). The payment callback never fails with an error page: on any error it redirects to `/#/booking/<id>?pay=checked`, and an unknown reference goes to `/#/bookings`. A late payment for a time that is still free confirms the booking instead (see Unpaid try). | `applyVerifiedPayment`, `processReference`, `requestRefund`, `src/sweep.ts` |
| Amount check | Gateway amount must equal price plus the booking fee (or a plausible processing fee on top: ≤ 8 % or ₦200); otherwise not confirmed, left for staff. | `amountMatches` in `src/paystack.ts` |
| Admin removes customer/barber | Upcoming bookings cancelled; paid online ones flagged NEEDS_REFUND and refunded; plan sessions/credits restored. Soft delete restorable **30 days**; **hard delete refused when a successful payment exists**. | `src/adminDelete.ts` |
| **Plan limits** | Price (settings `min/max_plan_price`, defaults ₦1,000–₦500,000), validity ≤ `max_plan_validity_days` (**90**), sessions ≤ `max_plan_sessions` (**30**). Purchase snapshot of terms; edits affect only future buyers. Active only after verified payment; validity counted from payment. Unused sessions: `plan_refund_policy` **NONE** (default) or MANUAL (display only). Never-paid plan checkouts deleted after `retention_checkout_days` (**2**) after a gateway check. | `src/plans.ts`, `src/sweep.ts`, migrations 004, 011 |
| Plan session use | Needs a valid plan with the service included and the appointment on or before expiry; one session per booking. | `claimEntitlement` |
| **Fee model (pay now)** | The customer pays price + **booking fee**. The processor (Paystack) fee is estimated from admin settings (`ps_percent`, `ps_flat`, flat waived below a threshold, cap, VAT on top) on the total and split three ways by `fee_share_customer/barber/platform_pct` (sum to 100, validated, audited). Customer's share = booking fee; barber's share and **TrimSlot's charge** (`charge_percent` + `charge_flat`, minimum `charge_min`, never above price, per-barber override possible) are taken from the payout. **Payout = price − barber's share − charge.** Sent to Paystack as subaccount split (`transaction_charge`, bearer = account) so the real settlement matches. The estimate is frozen on the booking; the real fee from verify is stored (`ps_fee_actual_kobo`) for reporting. Defaults: 33.33 % each, charge 2 % min ₦50. No fixed Paystack number is quoted to users. | `src/fees.ts`, `src/ledger.ts`, `src/paystack.ts`, `src/bookingService.ts` |
| **Fee model (pay on arrival)** | No Paystack part and no booking fee; only the TrimSlot charge applies, via the cash commission below. | `offAppBreakdown` |
| **Refund of the booking fee** | A refund returns price + booking fee; a credit is for the price only. Open lawyer question 24b. | `src/refundFlow.ts` |
| **Cash commission** | On a COMPLETED, PAID **pay-on-arrival** booking: debt = `commission_factor` (default **0.5**, shown publicly as **50 %**) × TrimSlot's charge for that price; one ledger row per booking; setting `commission_enabled`. | `accrueCommission`, `src/ledger.ts` |
| **Netting** | On the barber's next online payments, the platform charge is raised by up to the outstanding debt, never beyond it, and so the barber keeps at least `min_barber_payout_percent` (default **50 %**) of the amount; FIFO; applied to the ledger only when the payment is confirmed; reversed on refund. The netted amount is fixed when the checkout starts. If the debt is settled in the meantime (for example by a manual settlement) the payment is "over-netted": the barber's share is already cut by the extra, an audit row `LEDGER_OVERNETTED` is written, and nothing is paid back automatically (staff review). | `nettableKobo`, `planCheckoutSplit`, `applyNettingForPayment`, `reverseNettingForPayment` |
| **Refunds, chargebacks and the barber's balance** | **No mechanism.** A refund (cancel in time, not served, duplicate, late, slot-taken) is requested from Paystack for the whole amount charged; the app does not take anything back from the barber's commission balance or later payouts, and chargebacks are not handled in the app at all. How Paystack reverses a split payment on refund is Paystack's behaviour and has not been tested in live mode. The only barber-side reversal is netting (debt returns when a netted payment is refunded). | `src/refundFlow.ts`, `src/ledger.ts` |
| Balance limits | `ledger_max_debt` and `ledger_max_age_days` (default **0 = no limit**). If exceeded, the shop stops offering pay-on-arrival (that is all the code does; **no automatic suspension**). Reminders go to a barber whose oldest owed commission is over 7 days old or who is over a limit, at most every 3 days. Admin can waive/adjust/settle manually and suspends manually. | `ledgerBlocked`, `sendLedgerReminders` |
| **Payout set-up** | Barber picks bank (Paystack list, cached 6 h), enters 10-digit account; name looked up with Paystack (retry once); if lookup unavailable barber types the name (flag `payout_name_verified = false`); subaccount created at Paystack; we store bank name, **last 4 digits**, account name, subaccount code. Without payout set-up customers can only pay on arrival (production requires payout). Paystack **test mode** allows only 3 real-account lookups per day. | `src/payouts.ts`, migration 010 |
| **Shop approval** | Statuses PENDING, NEEDS_INFO, REJECTED, VERIFIED, SUSPENDED; only VERIFIED shops are visible/bookable; suspension reversible. | `src/admin*.ts` |
| Maintenance mode | Admin switch pauses new bookings and plan purchases with a message; existing bookings continue. | `platform_settings.maintenance_mode` |
| **Accounts** | Name, e-mail and/or phone (at least one), password (bcrypt). JWT in HttpOnly cookie `trimslot_token`, **7 days**, SameSite=Lax, Secure in production. Suspended/banned accounts are treated as logged out. Failed-login lock after 8 in 15 min per account; rate limits per IP. | `src/auth.ts`, `src/security.ts` |
| Age | No age check in the app; no date of birth collected. There is **no feature for booking on behalf of a child**. | — |
| Reviews / reports | Reviews for completed visits (barber can reply, admin can hide). Reports with categories NO_SHOW, BEHAVIOUR, PAYMENT, QUALITY, SAFETY, OTHER (message 5–1000 chars) go **only to admin**: the reported person does not see them in the app. | `src/app.ts`, `src/admin2.ts` |
| Reliability label | "New / Reliable / Mostly reliable / Often misses" with counts, shown to barbers about customers. | `reliabilityOf` in `src/smart.ts` |
| Private barber notes | Barber can store a note about a customer; visible only to that barber. | `barber_customer_notes` |
| Push | Web Push (VAPID); subscription = endpoint + keys + `user_agent` (the browser's description) stored with the user. The endpoint is unique: if another account turns push on in the same browser, the row **moves to that account**. Removed when the push service reports it gone or on unsubscribe, after repeated failures, or when unused for `retention_push_stale_days`. Reminders about 2 h and 30 min before; "your turn"/queue messages. In-app notifications always stored. The consent card shown is short ("Never miss your turn"); see document 06. | `src/push.ts`, `src/smart.ts`, `public/notify.js` |
| Data storage | Supabase Postgres, **eu-west-2 (London)**; Vercel functions region **lhr1 (London)**. Shop photo stored in the database (≤ 300 KB). | Supabase project, `vercel.json` |
| Retention automation | A job throttled to at most once an hour, started from the sweep (`/api/cron/sweep`). The sweep runs **daily** (Vercel cron `0 3 * * *`, Hobby plan limit) unless an external one-minute timer is set up (DEPLOY.md section 7); "Run clean-up now" in admin Controls (PIN) also runs it. It deletes: rate-limit rows (`retention_rate_limit_hours`, 2 h; these rows hold the IP address and, for failed log-ins, the typed identifier); payment webhook events (`retention_events_days` 400; invalid-signature ones `retention_bad_events_days` 30); notifications (`retention_notifications_days` 180); stale push subscriptions (`retention_push_stale_days` 60); admin alerts (`retention_admin_alerts_days` 90); soft-deleted users past `retention_deleted_days` (30): erased when no successful payment exists, otherwise anonymised; soft-deleted reviews, reports, and plans without purchases after the same window; abandoned plan checkouts (`retention_checkout_days` 2). Bookings, payments, refunds and the audit trail are kept (anonymised after account deletion). All periods are admin settings. | `src/retention.ts`, `src/sweep.ts`, `vercel.json`, migration 011 |
| Self-service rights | **Download my data** (`GET /api/me/export`, JSON; no password hash; barber private notes excluded). **Delete my account** (`POST /api/me/delete`, password + typing DELETE): customers are deleted at once unless they have upcoming bookings (blocked) and must acknowledge losing unused plan sessions/credits; barbers are deleted at once only with no upcoming bookings, no commission owed and no active customer plans, otherwise a deletion **request** is recorded and an admin alert raised (can be cancelled). Deletion = anonymisation: name, contact, picture, notifications, favourites, waitlist, notes and push subscriptions removed; payments, bookings and the audit trail kept without the name. | `src/accountData.ts` |
| Logs | Request log lines contain method, path, status, IP and user ID (stdout → Vercel). | `src/logger.ts`, `src/app.ts` |
| **Editable published numbers** | Cancel lock, how long a pay-now try stays open, credit expiry, refund auto-approve hours, fee %, flat fee, commission factor, liability cap, plan limits, retention periods and document versions are all admin settings (Controls page and Platform rules), validated server-side and audited (`SETTINGS_UPDATED` with before/after). The public pages (Terms, Privacy, Refunds, Plan Terms, Cookies, Barber Agreement) fill these numbers in live from `GET /api/public-settings` (no secrets, cached 60 s). The liability cap is **0 = not set** and the Terms then shows a placeholder. | `src/plans.ts`, `src/publicSettings.ts`, `public/legal-live.js` |
| **What is published** | `GET /api/public-settings` serves only the numbers the public pages quote (cancel window, payment hold, credit expiry, plan limits, retention periods, liability cap, loyalty, versions). Fees, charge, the processing-fee split, commission, payout floor, debt limits and the refund auto-approve time are NOT served; `legal/build.py` refuses to build a public page that quotes them. | `src/publicSettings.ts`, `legal/build.py` |
| **Admin alerts** | In-app list + web push to the admin for: refund waiting, refund auto-approved, refund failed (12 h dedupe), payment mismatch (24 h dedupe), barber deletion request. Per-event in-app/push preferences and optional quiet hours (default 22:00–07:00 Lagos, off) hold pushes until quiet hours end. Admin push subscriptions are separate from customer ones. | `src/adminNotify.ts`, `public/admin5.js`, `public/sw.js` |
| **Customer profile picture** | Customers only, optional. Cropped to a square and compressed to a ≤ 100 KB JPEG in the browser (server limit 120 KB, type checked by content), stored in the database (`user_avatars`) like the shop photo. Visible to the customer, to a barber who has a booking or waitlist entry with them, and to admin. Admin can remove a photo with a reason (customer notified, audited). Deleted with the account. | `src/avatars.ts`, `public/account.js` |
| Refund decision rights | TrimSlot staff decide. Approve needs the admin PIN; reject needs a written reason; **auto-approve** (after `refund_auto_approve_hours`, system actor, no PIN, done by the sweep so it can lag until the next sweep run) needs neither. Legacy `CREDIT_PENDING` rows from before this rule stay resolvable by staff (credit or refund, never both) in "Refund decisions"; no data was migrated. | `src/refundFlow.ts`, `src/admin.ts` |
| Terms acceptance | Sign-up requires a tick-box: customers accept Terms + Privacy; barbers also the Barber Agreement. Each acceptance is stored in `consent_log` (document, version, time, source, IP, user agent; IP and user agent are nulled when the account is deleted). Versions are admin settings (`terms_version`, `privacy_version`, `barber_agreement_version`); when one is raised every user without the new version sees a blocking re-accept page. Admin sees the history in the user record. Accounts created before this existed have no record and are asked at next login. | `src/accountData.ts`, `public/account.js`, migration 011 |
